Dashboards (`/student`, `/employer`, `/admin`) need a logged-in, email-verified user with the matching role
(checked in `proxy.ts`, again in each dashboard layout, and finally by database RLS). Admins can only be created
by the SQL step below; nobody can register as admin.

**Milestone:** Phase 2, Stage D (authentication) implemented and locally tested; real-Supabase verification pending.
Full details, test results and the security verification table: `PHASE2_PROGRESS.md`.

Requirements: Node.js 20 or newer (`node -v`) and npm.

## Run locally (Windows: PowerShell in VS Code)

```powershell
npm install
npm run dev        # http://localhost:3000
```

The public pages work without any configuration.

## Connect your own Supabase project

1. Create a free project at https://supabase.com/dashboard.
2. Project Settings -> API (or "API Keys"): copy the **Project URL** and the **publishable** key (`sb_publishable_...`).
3. Copy `.env.example` to `.env.local` and fill in the two values:
   ```powershell
   Copy-Item .env.example .env.local
   ```
4. Restart `npm run dev`.

Never paste keys into chat, never commit `.env.local` (it is git-ignored), and never use the **secret / service_role** key in this app.

## Create the database

Open Supabase -> SQL Editor, and run the six files in `supabase/migrations/` **in numeric order**
(paste each file, press Run, wait for "Success", then the next). They create the tables, security
rules, triggers, storage buckets and reference data (job categories and skill names only; no fake companies or jobs).

## Create the first admin

Admins cannot be created from the website. After you sign up normally (Stage D), run this once in the SQL Editor:

```sql
update public.profiles set role = 'admin', onboarded_at = coalesce(onboarded_at, now())
where id = (select id from auth.users where email = 'YOUR-EMAIL@example.com');
```

## Google and GitHub sign-in (Stage D addendum)

Buttons are on `/login` and `/register`. Provider client secrets live only in Supabase (Auth → Providers).
In Supabase → Auth → URL Configuration, the Redirect URLs list must allow `http://localhost:3000/auth/callback`
(or `http://localhost:3000/**`). First-time social users choose Student or Employer on `/onboarding`.
**This needs migration `20261102000007_social_onboarding.sql`** (already applied to the founder's live project; apply it to any new Supabase project after 001-006): it adds
`profiles.onboarded_at`, a one-time `complete_onboarding()` function and a tighter profile guard. Read the
comments at the top of the file before applying it.

## Test the database security (no Supabase needed)

```powershell
npm run test:db
```

Applies all migrations to a temporary in-memory Postgres and tries to break them
(self-promotion to admin, duplicate applications, reading other people's resumes, and more).
It uses small stand-ins for Supabase's `auth` and `storage` schemas, so it proves the StudoJob
rules but is not a substitute for testing on the real project.
